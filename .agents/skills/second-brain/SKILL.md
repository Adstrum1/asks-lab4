# Second Brain Knowledge Management Skill

Ця навичка регламентує правила та процедури роботи з персональною навчальною базою знань (PKM / Second Brain) у межах курсу **"Архітектура спеціалізованих комп’ютерних систем • 2026"**.

---

## 🎯 Основні задачі навички

1. **Класифікація за методологією PARA**:
   - `Inbox` — необроблені вхідні конспекти, швидкі нотатки з лекцій, тимчасові ідеї.
   - `Projects` — поточні навчальні задачі з чітким дедлайном і результатом (лабораторні роботи, розрахунково-графічні роботи, підготовка до колоквіумів).
   - `Areas` — довгострокові навчальні предмети та розділи знань ("Архітектура процесорів", "Конвеєризація", "Організація пам'яті").
   - `Resources` — довідники, таблиці команд (RISC-V, ARM, x86), специфікації, шпаргалки.
   - `Archives` — успішно здані лабораторні роботи, матеріали минулих семестрів, застарілі чернетки.

2. **Семантичне тегування**:
   - Формування лаконічних, структурованих тегів у нижньому регістрі через дефіс: `#аскс-2026`, `#конвеєр`, `#кеш-пам'ять`, `#лабораторна`, `#risc-v`.
   - Забезпечення узгодженості тегів між різними нотатками та уникнення дублювання синонімів.

3. **Побудова зв'язків (`[[Wiki-links]]`)**:
   - Виявлення перехресних посилань між пов'язаними темами:
     - Прив'язка лабораторних проєктів до теоретичних розділів: `[[Організація пам'яті та кешування]]`.
     - Прив'язка понять до довідкових матеріалів: `[[Специфікація системи команд RISC-V]]`.
   - Контроль цілісності зв'язків (фіксація посилань на ще не створені нотатки для подальшого опрацювання).

4. **Стисле підсумовування (Summarization)**:
   - Створення містких блоків `TL;DR / Коротке резюме` на початку нотатки (1–3 речення).
   - Виділення ключових формул, схем, параметрів та висновків без зайвої "води".

---

## ⛔ Критичні правила та обмеження (Guardrails)

### 1. Академічна доброчесність: Жодних вигаданих джерел
- **НІКОЛИ не вигадувати джерела**, літературу, підручники, авторів, сторінки чи посилання.
- Якщо джерело відоме з навчальних матеріалів курсу "Архітектура спеціалізованих комп’ютерних систем • 2026" — вказувати його точно (назва лекції, номер методички, офіційна специфікація).
- Якщо джерело відсутнє або непевне — явно вказувати `[Джерело потребує уточнення]` або запитувати джерело у користувача.

### 2. Безпека файлової системи
- **НІКОЛИ не видаляти та не переміщати файли нотаток без прямого явного підтвердження користувача.**
- Зміна категорії нотатки в метаданих (`category: Projects` тощо) оновлює лише YAML frontmatter, а не фізичне розташування файлу на диску, якщо користувач окремо не дав команду на переміщення.

### 3. Обов'язковий підсумковий журнал змін
- Наприкінці кожної операції обов'язково формувати табличний або маркований **Журнал запропонованих змін (Proposed Changes Log)**.

## 📋 Стандарт структури навчальної нотатки

Кожна навчальна нотатка повинна містити YAML frontmatter:

```markdown
---
title: "Назва теми / нотатки"
created: "2026-11-10T14:00:00+02:00"
updated: "2026-11-10T14:00:00+02:00"
tags:
  - аскс-2026
  - тема
status: "В процесі" # Варіанти: Чернетка | В процесі | Завершено | В архіві
type: "Конспект"   # Варіанти: Конспект | Поняття | Література | Завдання | Резюме
category: "Areas"  # Варіанти PARA: Inbox | Projects | Areas | Resources | Archives
---

# Назва теми / нотатки

> **TL;DR / Коротке резюме:** Стисла суть теми, основний висновок або призначення.

## Ключові концепції
- Пункт 1
- Пункт 2

## Практична частина / Приклади
\`\`\`
// Код, асемблер, команди або діаграми
\`\`\`

## Зв'язки
- Дотична тема: [[Назва іншої нотатки]]
- Базове поняття: [[Базовий концепт]]

## Джерела
1. Назва конспекту / методичних вказівок (лише реальні джерела).
```

## 📑 Обов'язковий формат Журналу запропонованих змін

Після завершення обробки нотатки агент завжди формує підсумок у такому форматі:

```markdown
### 📋 Журнал запропонованих змін

| Параметр | Значення |
| :--- | :--- |
| **Нотатка / Файл** | `notes/areas/...` ("Назва нотатки") |
| **Категорія PARA** | `Areas` (аргументація віднесення) |
| **Тип та статус** | `Конспект` / `В процесі` |
| **Призначені теги** | `#аскс-2026`, `#тег1`, `#тег2` |
| **Створені зв'язки [[...]]** | `[[Тема 1]]`, `[[Тема 2]]` |
| **Коротке резюме** | 1-2 речення суті матеріалу |
| **Джерела** | Вказані реальні джерела / `[Джерело потребує уточнення]` |
| **Дії з файлами** | Файли не видалялися і не переміщувалися |
```
